# CodexPlusBar 1.7.6

## Account Priority 0.2.0

- Prefer eligible accounts with **exactly 100% weekly (7D) quota remaining**, regardless of remaining subscription days, so their first use can start the weekly reset countdown.
- If several accounts have full weekly quota, select the earliest verified subscription expiry.
- When no eligible account has 100% weekly quota, use the existing earliest-expiry rule. Fresh observations below 100% return an account to normal expiry ordering.
- Keep existing identity, freshness, subscription, five-hour quota and cooldown checks. Unavailable weekly quota is not full quota. Equal expiry within a priority tier retains the eligible current account, then uses stable identity ordering.
- Paused previews and automatic selection use the same policy. CodexPlusBar remains the source of fresh account observations.

## Install or update the Mac app

1. Download **[CodexPlusBar.dmg](https://github.com/withLinda/CodexPlusBar/releases/download/v1.7.6/CodexPlusBar.dmg)** for macOS 14 or later, Apple silicon or Intel.
2. Quit CodexPlusBar. If its menu is missing, open it from Applications and press **⌘Q** in its window.
3. Open the DMG, drag **CodexPlusBar.app** to **Applications**, and choose **Replace** when updating.
4. Eject the DMG and reopen CodexPlusBar from Applications. Refresh your accounts and keep the app running.

The app is version **1.7.6**, build **29**, and retains the earlier startup, account-refresh and iCloud fixes. Saved profiles and sign-ins remain in place. iCloud Sync stays opt-in on each Mac.

## Install or update the extension separately

The new selection rule requires this release's freshly built **[expiry-selector.zip](https://github.com/withLinda/CodexPlusBar/releases/download/v1.7.6/expiry-selector.zip)**, containing Account Priority **0.2.0**. Updating only the DMG does not update the extension.

1. For an existing installation, choose **Pause Auto** and wait for acknowledgement.
2. Download and extract the ZIP. Install or replace the **expiry-selector** folder through **OpenChamber → Settings → Extensions**, approving its plugin and local-service capabilities.
3. Confirm package version **0.2.0**, recheck account evidence, disable competing native limit-switch/fallback settings, and explicitly enable or resume Auto.

Verified compatibility remains **OpenChamber 2.7.0 / OpenCode 2.2.6**. See the [extension guide](../../Extensions/expiry-selector/README.md) for eligibility, shared selection and recovery details.
