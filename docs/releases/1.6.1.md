# CodexPlusBar 1.6.1 (build 21)

## Fix: Account Priority shows Unknown expiry

ChatGPT returns some account entries twice: once under the canonical account ID and once as an identical `default` entry. CodexPlusBar 1.6.0 correctly kept display normalization separate from selector evidence, but then rejected this harmless mirror as ambiguous. The panel received quota observations but no subscription expiry.

The decoder now removes only an **exact default mirror** with an explicit account ID and a matching canonical dictionary key. It compares the complete JSON payload, preserving boolean versus numeric types. Conflicting expiry, flags, extra fields, other duplicate rows, and unrelated default accounts remain subject to the existing rejection rules. This does not introduce a default-account expiry fallback.

## Install

1. Download [CodexPlusBar.dmg](https://github.com/withLinda/CodexPlusBar/releases/download/v1.6.1/CodexPlusBar.dmg), quit CodexPlusBar, and replace it in Applications.
2. Reopen CodexPlusBar and refresh your accounts. Expiry evidence is rebuilt from fresh account responses.
3. In Account Priority, choose **Recheck** and confirm expiry countdowns before enabling Auto.

The [OpenChamber extension ZIP](https://github.com/withLinda/CodexPlusBar/releases/download/v1.6.1/expiry-selector-0.1.0.zip) is included for new installations. It is the **unchanged 0.1.0 package**; existing installations do not need to reinstall it. The fix is in CodexPlusBar. Both packages are covered by [SHA256SUMS](https://github.com/withLinda/CodexPlusBar/releases/download/v1.6.1/SHA256SUMS).

## Separate Blocked warning

**Native limit switching or fallback is still enabled** means a competing OpenChamber setting is on. Disable native automatic account switching/fallback before using this selector. Record prior settings for rollback; pause and await acknowledgement before using native **Use**. The expiry fix does not bypass this ownership guard or automatically enable Auto.

## API and compatibility

No new API, endpoint, extension-version or wire-schema change. `AccountCatalogService.decodeCatalogEvidence(from:)` retains all display entries but omits verified identical canonical/default mirrors from its evidence list. Existing account+user checks, independent timestamps, strict quota flags, conflict rejection, and native OAuth ownership remain in force. See the [1.6.0 API reference](https://github.com/withLinda/CodexPlusBar/blob/v1.6.1/docs/releases/1.6.0.md).

macOS 14+, Apple silicon and Intel. Account Priority remains qualified for OpenChamber 2.7.0 / OpenCode 2.2.6.
