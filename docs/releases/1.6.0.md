# CodexPlusBar 1.6.0 (build 20)

## Downloads and installation

- [CodexPlusBar.dmg](https://github.com/withLinda/CodexPlusBar/releases/download/v1.6.0/CodexPlusBar.dmg): universal macOS 14+ app for Apple silicon and Intel.
- [expiry-selector-0.1.0.zip](https://github.com/withLinda/CodexPlusBar/releases/download/v1.6.0/expiry-selector-0.1.0.zip): Account Priority extension for OpenChamber 2.7.0 / OpenCode 2.2.6.
- [SHA256SUMS](https://github.com/withLinda/CodexPlusBar/releases/download/v1.6.0/SHA256SUMS): checksums for both packages.

Update the app **and** install the extension. Quit CodexPlusBar before replacing it from the DMG, reopen it, and refresh your accounts. Extract the ZIP, then install its `expiry-selector` folder through OpenChamber Settings → Extensions. Confirm the panel is paused and your accounts have the expected evidence. Record your current account and native limit-switch/fallback settings before disabling competing automation and enabling Auto.

## What changed

Account Priority selects the verified ChatGPT subscription with the fewest days remaining when both its 5H and applicable 7D quota are usable. A healthy 17-day subscription ranks ahead of a 30-day subscription. The panel shows countdowns such as **Expires in 16d 6h**, current/next account, freshness, exclusions, and acknowledged controls.

CodexPlusBar publishes sanitized observations and coordinates manual sign-in changes through maintenance holds. The extension uses native OpenCode activation and OAuth refresh. It preserves actual-request attribution across concurrent switches and HTTP/WebSocket header races. A quota failure from A cannot exhaust B just because B became active meanwhile.

## Operating boundaries

- First installation is paused. Pause and await acknowledgement before native **Use**; resume explicitly.
- Selection is global across locations. Already-resolved requests may finish on their original account; this is not per-session account assignment.
- Unknown/stale evidence never qualifies a replacement. No eligible account means the current account stays selected and native error handling continues.
- Retry handling covers attributed primary requests; auxiliary work retains native handling and the native retry ceiling remains in force.
- OpenCode versions other than 2.2.6 block Auto until qualified. Competing native failover must be absent in all attached locations.
- Live account installation/switch/rollback smoke tests remain unperformed. Publication was explicitly authorized after isolated acceptance; publication does not imply live-account acceptance or independent review.

## New shipped integration API

These interfaces were implemented in the preceding feature commits; the release commit changes version metadata and documentation only.

### Observation file, schema version 1

Path: `~/Library/Application Support/CodexPlusBar/Exports/openchamber-selector-v1.json`. Atomic 0600 file, 0700 export directory; at most 1 MiB / 256 accounts. Times are integer Unix milliseconds.

- Envelope: `schemaVersion`, `sourceInstanceID` (launch UUID), `sequence`, `generatedAtMs`, `catalogTrusted`, `accounts`.
- Account: `profileID`, `credentialID`, `identityKey` (SHA256 of accountID + newline + userID), `accountID`, display-only `label`, `bindingObservedAtMs`, nullable `usage`, nullable `entitlement`, `unavailableReasons`.
- Usage: `observedAtMs`, `identityKey`, explicit `allowed` / `limitReached`, `fiveHour { remainingPercent, resetAtMs }`, and `sevenDay` with `state: available` plus percentage/reset or `state: not-applicable`.
- Entitlement: `observedAtMs`, `accountID`, nullable `expiresAtMs` / `active`, `deactivated`, `usable`, and `match: canonical | unique-alias`.
- Heartbeat 30s; maximum heartbeat age 90s, usage age 15m, entitlement age 24h; future skew 30s. A heartbeat never refreshes evidence. Reset passage alone never proves replenished quota.

### Private selector control, protocol version 1

Origin: `http://127.0.0.1:53971`. Descriptor `~/.codexplusbar-selector/runtime.json` contains `protocolVersion`, `pid`, `epoch`, `port`, `bearer`; directory/file permissions are 0700/0600. Every request needs the descriptor's bearer and `X-Selector-Epoch`. JSON mutations require UUID `operationID` and at most 64 KiB; status clients allow at most 1 MiB. Browser-origin requests are rejected.

- `GET /v1/status`: returns status plus `protocolVersion` and `epoch`.
- `POST /v1/mode { operationID, mode: auto | paused }`: acknowledged mode change; Pause drains outstanding work; Auto schedules recheck.
- `POST /v1/recheck { operationID }`: rereads published evidence/native inventory; paused inspection does not resolve/activate credentials or refresh upstream account data.
- `POST /v1/maintenance/begin { operationID, reason: manual-account-change | sign-in-repair }`: persists paused state and returns `holdToken` after draining work.
- `POST /v1/maintenance/end { operationID, holdToken }`: releases the hold and returns status, leaving Auto paused.
- Status: `mode`, `blockedReason`, `supportedVersions`, `activeCredentialID`, `activeLabel`, `nextCredentialID`, `snapshotAgeMs`, `exclusions`, `holdsCount`, `lastSwitch`, `recentHistory`, `checking`, `accounts`, `snapshotGeneratedAtMs`, `nativeObservedAtMs`. Account status exposes credential ID/label, expiry, quota remaining and observation times, not identity/account hashes or secrets. History credential IDs may be null.
- Errors: 400 invalid request, 401 unauthorized, 403 browser origin, 404 unknown route, 405 wrong method, 409 epoch/control conflict, 413 oversized request, 500 local control failure. Mutations are idempotent while receipts are retained; active maintenance receipts are pinned. Never replay a mutation against a changed epoch.

### Host-managed service and persistence

- Host supplies `OPENCHAMBER_SERVICE_PORT` and `OPENCHAMBER_SERVICE_TOKEN`; the service binds loopback and requires its separate host bearer.
- `GET /health` returns `{ ready: true }`; it confirms service availability, not selector eligibility.
- Service exposes only status/mode/recheck routes above, with sanitized status responses. It does not expose maintenance or credentials. Verified control refusal returns 409 with status; unavailable/unverified ownership returns 503. The panel never receives the selector bearer.
- `~/.codexplusbar-selector/state.json`: schema/policy versions, desired mode, identity-keyed cooldowns, bounded redacted history, maintenance recovery flag. No OAuth tokens. Corrupt state or unfinished maintenance prevents Auto.
- Swift integration: `SelectorExportPublishing` lifecycle/update/invalidation and begin/complete-refresh tickets; `SelectorControlClient` status/begin/end maintenance; `SelectorMaintenanceContext` carries and revalidates ownership through async mutation and consumed-token recovery. The app runtime injects the production publisher; test/controller defaults do not publish to real home.
- Package: extension `codexplusbar-expiry-selector` 0.1.0, OpenChamber manifest API 1, bundled plugin/service and classic-script SDK panel; no runtime dependency installation or `provides: [opencode]` bridge.
