# CodexPlusBar 1.7.1 — Profile refresh fix

Universal macOS 14+ installer for Apple silicon and Intel. Version **1.7.1**, build **24**.

## What this fixes

Version 1.7.0 could fail every profile refresh with **“Cloud sync storage must use private, regular files outside the account folder.”** The same path error affected browser open, sign-in, cookie sync, and clearing, even with iCloud Sync off.

The browser recovery store's default path was inside the account folder, but its validator correctly required storage outside that folder. Refresh checked recovery before requesting usage, so it stopped before reaching OpenAI.

Recovery now uses the private sibling directory `~/Library/Application Support/CodexPlusBar.browser-recovery`. Private ownership/permissions and protection against redirected paths remain enforced. Existing profiles, cookies, passwords, and native saved logins do not need to be deleted or reset.

## Install the fix

1. Download [CodexPlusBar.dmg](https://github.com/withLinda/CodexPlusBar/releases/download/v1.7.1/CodexPlusBar.dmg).
2. Quit CodexPlusBar, open the DMG, and drag **CodexPlusBar.app** onto **Applications**. Choose **Replace**.
3. Eject the DMG, reopen CodexPlusBar from Applications, and choose **Refresh all**.

The app and DMG are Developer ID-signed, notarized, and stapled. Download `SHA256SUMS` beside the DMG and run `shasum -a 256 -c SHA256SUMS` from their download folder to verify the file.

- After the fix, **30 tests in two suites passed**: browser session adoption/recovery and profile data service. Checks cover absent recovery storage, private save/restart/remove, ordinary session/usage/expiry refresh, browser actions, and continued rejection of account-tree and redirected paths.
- No full test suite was run. Tests use synthetic credentials and controlled external-service responses.
- The fresh strict universal archive, five release-preflight tests, app/DMG notarization, staple validation, Gatekeeper, mounted-app Production preflight, and final checksum passed.
